
# Predictive Intelligence Project Onboarding Runbook

**Document purpose:** Provide a repeatable onboarding path for new team members joining the Predictive Intelligence (PI) project.

**Project:** Predictive Intelligence 
**Last updated:** November 2, 2026 

## 1. Purpose and scope

This runbook captures the initial access and setup steps shared for onboarding to the Predictive Intelligence project. It is intended for new project team members and should be maintained as tools, owners, and access procedures change.


## 2. Onboarding checklist

Complete the steps below in order where possible. Some requests may run in parallel; access approval and provisioning times are not specified here.

-  Get added to the WDT Predictive Intelligence Teams channel.
-  Request access to GitHub Enterprise.
-  Request Claude Code and GitHub Copilot access from Natalie Lorati.
-  Install and set up Okta Verify using Deloitte credentials.
-  Sign in to Deloitte CMS and use it to request ServiceNow and other environment access.
-  Request PI-related cloud and tool access from Manikandan Elangovan and Deepak Basnet.
-  Confirm access works and can reach the project resources needed for your role.

## 3. Step-by-step onboarding

### Step 1 — Join the project Teams channel

Request access to the **WDT Predictive Intelligence** Teams channel. Use the channel to find project details and documents.

**Request:** Ask the project team or the appropriate channel owner to add you. The channel owner and exact access-request method were not provided; confirm them with your project contact.


### Step 2 — Request GitHub Enterprise access

Open [Deloitte GitHub Enterprise](https://engineeringplatforms.deloitte.com/github-enterprise) and follow the available access-request process.


### Step 3 — Request Claude Code and GitHub Copilot

Contact **Natalie Lorati** to request access to **Claude Code** and **GitHub Copilot**.

**Include in your request:** Your project name (Predictive Intelligence), role, and the tools requested. Follow any instructions provided for approvals or account setup.


### Step 4 — Set up Okta Verify

Install **Okta Verify** on your mobile device and sign in using your Deloitte credentials. Complete any prompts shown during enrollment.


### Step 5 — Sign in to Deloitte CMS

Open [Deloitte CMS](https://deloittecms.digitalidentityservice.com/app/UserHome) and sign in. CMS is identified as the starting point for ServiceNow and other environment access.

**Next:** Use the access-request options available in CMS for the ServiceNow or environment access required for your role.


### Step 6 — Request cloud and PI tool access

Contact **Manikandan Elangovan** and **Deepak Basnet** to request access to the cloud environments and tools needed for PI work, including **AWS**, **Databricks**, and any other applicable tools.

**Include in your request:** Project name, role, business need, requested environments/tools, and any account or environment details requested by the access process. Do not request broad permissions by default; request the minimum access needed for assigned work.



## 4. Completion and handoff

Before considering onboarding complete:

1. Confirm that each requested access item is either granted or has a named follow-up owner.
2. Test access to the resources required for your initial assignments.
3. Record unresolved access requests, blockers, and next actions in the project’s approved tracking location.
4. Ask your project lead or manager to confirm any role-specific setup not covered here.

## 5. Troubleshooting and escalation

- **Request status unclear:** Follow up with the person or support channel that owns the request; include the request date and any ticket or reference number.
- **Sign-in or MFA issue:** Use authorized Deloitte identity or service support. Never send passwords, MFA codes, or sensitive authentication details in chat or email.
- **Tool or environment not listed:** Confirm with the project lead which access is required for your role before submitting a request.
- **Approval or provisioning delay:** Keep the project contact informed and track the dependency so onboarding work can be planned accordingly.
